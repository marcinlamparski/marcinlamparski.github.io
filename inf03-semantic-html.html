Czym jest semantyka HTML?

Tag semantyczny niesie informację o znaczeniu treści — dla przeglądarki, czytnika ekranu (NVDA, JAWS), wyszukiwarki (SEO) i innego programisty czytającego kod.

Tag niesemantyczny (<div>, <span>) to pusty kontener — opisuje wygląd lub układ, ale nie mówi nic o roli treści w dokumencie.

Efekt wizualny może być identyczny — różnica leży w warstwie znaczeniowej (DOM, accessibility tree, schema.org). Na egzaminie INF.03 liczy się umiejętność wyboru właściwego tagu.

Tag Znaczenie semantyczne Kiedy stosować?
<header>

Nagłówek strony lub sekcji

Logo, tytuł, nawigacja. Może pojawić się wewnątrz <article>.
<nav>

Blok nawigacyjny

Tylko do głównych zestawów linków. Nie każda lista linków to <nav>.
<main>

Główna, unikalna treść strony

Tylko jeden na stronę. Nie obejmuje headerów, nav, stopki.
<article>

Samodzielna, kompletna treść

Post blogowy, artykuł, news, komentarz. Może istnieć poza stroną.
<section>

Tematyczna sekcja dokumentu

Powinna mieć nagłówek (h2–h6). Nie zastępuje <div> dla stylowania.
<aside>

Treść poboczna, luźno powiązana

Sidebar, box z ciekawostką, reklama, powiązane artykuły.
<footer>

Stopka strony lub sekcji

Może wystąpić wewnątrz <article> — autor, data, tagi.
<figure>

Ilustracja, wykres, blok kodu

Treść, do której odwołuje się tekst, ale która może być wyciągnięta poza przepływ.
<figcaption>

Podpis do <figure>

Pierwsze lub ostatnie dziecko <figure>.
<details>

Rozwijana sekcja (bez JS)

Natywny akordeon. Atrybut open — domyślnie rozwinięty.
<summary>

Widoczny nagłówek <details>

Klikalna etykieta akordeonu.
<address>

Dane kontaktowe autora/firmy

Nie do adresów pocztowych w środku treści — tylko do kontaktu powiązanego z dokumentem.
<dialog>

Natywne okno dialogowe / modal

Metoda .showModal() otwiera z trybem focus-trap. HTML5.1+.

Pytanie / sytuacja Poprawny tag Błędny wybór

Chcę wyświetlić kursywę dla tytułu książki

 <cite> <em> — em to nacisk logiczny, nie tytuł

Chcę przekreślić starą cenę (nieaktualną)

 <s> <del> — del oznacza usunięcie w historii edycji

Chcę zaznaczyć fragment jako wynik wyszukiwania

 <mark> <strong> — strong to ważność, nie trafność

Chcę wyświetlić skrót „HTML" z rozwinięciem po najechaniu

 <abbr title="HyperText..."> <span title="..."> — traci semantykę skrótu

Kontener na logo + menu górne

 <header> <div id="header"> — brak roli w drzewie dostępności

Lista linków do mediów społecznościowych w stopce

 <ul><li><a> <nav> — nav tylko dla głównych zestawów nawigacji

Klawisz na klawiaturze w instrukcji obsługi

 <kbd> <code> — code to fragment kodu, nie klawisze

Wynik wyświetlony przez program (output)

 <samp> <code> — code to kod źródłowy (input), nie output

Semantyczny vs niesemantyczny — zestawienie

✓ Zalety semantycznych tagów

  • <nav> — czytnik ekranu ogłasza „obszar nawigacji", użytkownik może go pominąć
  • <main> — skrót klawiszowy w NVDA/JAWS przenosi wprost do treści
  • <article> — Google wyodrębnia treść do rich snippets (schema.org)
  • <time datetime="..."> — wyszukiwarka zna dokładną datę, może filtrować
  • <strong> — czytnik ekranu zmienia ton głosu przy słowach ważnych
  • <figure>/<figcaption> — powiązanie obrazu z podpisem w drzewie dostępności
vs

✗ Wady niesemantycznych tagów

  • <div id="nav"> — brak roli ARIA, czytnik ekranu ignoruje strukturę
  • <div id="main"> — wymaga ręcznego dodania role="main", łatwo zapomnieć
  • <div class="article"> — wyszukiwarki nie rozpoznają struktury, gorszy SEO
  • <span> + CSS — żadnych metadanych daty, przeglądarki nie mogą parsować
  • <b> — tylko wygląd, zmiana stylu CSS nie zmienia znaczenia
  • <div><img><p> — brak logicznego powiązania między obrazem a opisem
